1. INTRODUCTION                                 *mdview* *mdview-introduction*

mdview renders markdown in the buffer you are editing. Headings get an icon
and a tinted row, list bullets and checkboxes get glyphs, block quotes get a
bar, thematic breaks get a rule across the window, and fenced code blocks lose
their fences and gain a background. A ```diff block is coloured per row, the
way a forge shows one.

Nothing is written to the buffer. Every effect is an extmark -- conceal,
inline virtual text, a line highlight, a virtual line -- so the file on disk
is untouched, undo is untouched, and `:w` writes exactly what you typed.

The line the cursor is on always shows its raw source, so it can be edited.
Move off it and it renders again.

Rendering is per buffer and is on by default for markdown files. It costs
roughly one window's worth of work per redraw, not one document's.

==============================================================================
2. REQUIREMENTS                                          *mdview-requirements*

- Neovim 0.11 or newer. mdview hides fence rows with the `conceal_lines`
  extmark field, which is new in 0.11. Developed and verified against 0.11.4.
- A treesitter parser for `markdown`. Neovim 0.11 bundles one, so in practice
  there is nothing to install. Without it mdview draws nothing at all; it does
  not error.
- A font with the icon glyphs in |mdview-options-glyphs|. The heading, bullet
  and quote defaults are ordinary geometric shapes present in most fonts; the
  two checkbox defaults are Nerd Font glyphs. If they render as boxes, set
  |g:mdview_CheckedIcon| and |g:mdview_UncheckedIcon| to something your font
  has.
- 'termguicolors', or a GUI, for the background tints. Without true colour
  mdview skips them outright rather than guessing; the glyphs, the rules and
  the concealment all still work.

Inline markup -- bold, italic, code spans, links -- is not mdview's, and needs
treesitter highlighting on for markdown. See |mdview-inline|.

==============================================================================
3. INSTALLATION                                          *mdview-installation*

Any plugin manager, or an ordinary 'runtimepath' entry. With lazy.nvim: >lua

    {
        "mdview",
        dir = "~/plugins/mdview",
        ft = "markdown",
        -- Options are read by plugin/mdview.vim as it is sourced, so they
        -- have to be set before the plugin loads: init, not config.
        init = function()
            vim.g.mdview_DiffPalette     = "github"
            vim.g.mdview_DiffDeleteColor = 0xEB6F92
        end,
        config = function()
            vim.keymap.set("n", "<leader>zm", vim.cmd.MdviewToggle)
        end
    }
<
The `init` / `config` split matters. lazy.nvim runs `config` after the
plugin's files have been sourced, and the colour options are read at source
time to compute the highlight groups. Set those in `init`. See
|mdview-options-timing| for which options are which, and for the escape hatch
if you set one late anyway.

Run `:helptags ALL` after installing to build this file's tags.

                                                            *g:loaded_mdview*
Setting `g:loaded_mdview` before startup stops the plugin loading at all: >vim

    let g:loaded_mdview = 1
<
==============================================================================
4. USAGE                                                        *mdview-usage*

Open a markdown file. It renders. That is the whole of it, unless you have
turned |g:mdview_AutoEnable| off, in which case use |:MdviewEnable| or a
mapping to |:MdviewToggle|.

While a buffer is rendered:

    Action                          Effect ~
    Move the cursor onto a line     That line shows its raw source; every
                                    other line stays rendered.
    Edit                            The view follows the edit.
    Scroll, split, resize           The view re-renders for the new viewport
                                    and the new width.
    |:MdviewDisable|                 Everything mdview drew is removed and the
                                    window options it took are handed back.

mdview sets two window-local options in every window showing a rendered
buffer, and restores them when the buffer stops being rendered or the window
stops showing it:

    'conceallevel'      set to 2   -- without it nothing is concealed
    'concealcursor'     set to ""  -- this is what reveals the cursor's line

Both are restored to what they were, and only if mdview still holds them: an
option you or another plugin has since changed is left alone. Toggling on and
off leaves the window as it was found.

Because 'conceallevel' is window-local rather than buffer-local, a buffer open
in two windows is set up in both.

==============================================================================
5. COMMANDS                                                  *mdview-commands*

All three take no arguments, accept a following `|`, and act on the current
buffer.

                                                              *:MdviewToggle*
:MdviewToggle       Render the current buffer, or stop rendering it.

                                                              *:MdviewEnable*
:MdviewEnable       Render the current buffer. Does nothing if it is already
                    rendered. Works whether or not |g:mdview_AutoEnable| is
                    set -- that option gates only the automatic start on
                    |FileType|.

                                                             *:MdviewDisable*
:MdviewDisable      Stop rendering the current buffer: clears every extmark,
                    unbinds the buffer's autocmds, and hands back
                    'conceallevel' and 'concealcursor' in every window that
                    no longer shows a rendered buffer.

==============================================================================
6. WHAT GETS RENDERED                                       *mdview-rendering*

    Source                    Rendered as ~
    # Heading                 |g:mdview_HeadingIcons| for the level, in the
                              level's own colour, with the row tinted by
                              |g:mdview_HeadingBlend|. A closing `#` run is
                              hidden.
    Heading / =======         Underlined (setext) headings get the row tint
                              and nothing else. The underline stays visible;
                              see |mdview-limitations|.
    - item  * item  + item    |g:mdview_BulletIcons|, cycled by list nesting
                              depth.
    1. item   1) item         Recoloured with `MdviewOrdered`, and nothing
                              else. The digits are content, not syntax:
                              concealing them loses the number and replacing
                              them moves every column after it.
    - [x] done                |g:mdview_CheckedIcon| in place of the `[x]`;
                              the list bullet is hidden so the checkbox sits
                              where the bullet would have.
    - [ ] todo                |g:mdview_UncheckedIcon|, likewise.
    > quoted                  |g:mdview_QuoteIcon|, once per nesting level, on
                              the first line and every continuation.
    ---                       A rule of |g:mdview_RuleChar| across the
                              window's text width.
    ```                       Both fence rows are hidden and the body between
                              them is tinted by |g:mdview_CodeBlockBlend|.
    ```diff                   The same, plus per-row colour: `-` rows red,
                              `+` rows green, `@@` rows lavender, context rows
                              plain, and a rule above and below the body.
                              `patch` and `udiff` are treated the same way.
                              See |mdview-options-diff|.

An unclosed fenced block renders nothing until its closing fence is typed.
Rendering it would background the rest of the file the moment you opened one.

Tables are not rendered. Inline markup is not mdview's. Both are explained in
|mdview-limitations| and |mdview-inline|.

7. OPTIONS                                                    *mdview-options*

All options are Vimscript globals. Set them in `init.vim` / `init.lua`, or in
a lazy.nvim `init` block. `:let g:mdview_...` at runtime works too, subject to
|mdview-options-timing|.

------------------------------------------------------------------------------
7.1 Loading                                           *mdview-options-loading*

                                                        *g:mdview_AutoEnable*
Start rendering automatically when a buffer's 'filetype' is in
|g:mdview_Filetypes|. Turn it off to render only on |:MdviewEnable| or
|:MdviewToggle|, which work regardless. >vim

    let g:mdview_AutoEnable = 1
<
                                                         *g:mdview_Filetypes*
The filetypes |g:mdview_AutoEnable| acts on. >vim

    let g:mdview_Filetypes = ['markdown']
<
mdview reads the `markdown` treesitter tree whatever the buffer's 'filetype'
is, so adding a filetype here only works for one that markdown's grammar can
parse.

------------------------------------------------------------------------------
7.2 Glyphs                                             *mdview-options-glyphs*

Each glyph carries its own trailing space, because the marker it replaces is
concealed along with the space that followed it. Drop the space and the text
moves left.

                                                      *g:mdview_HeadingIcons*
One entry per heading level, `#` through `######`. >vim

    let g:mdview_HeadingIcons = ['◈ ', '◆ ', '▸ ', '▹ ', '· ', '· ']
<
                                                       *g:mdview_BulletIcons*
Drawn in place of `-`, `*` and `+`, cycled by list nesting depth: the first
entry at the outermost level, wrapping round when the list is deeper than the
list is long. >vim

    let g:mdview_BulletIcons = ['● ', '○ ', '◆ ', '◇ ']
<
                                                       *g:mdview_CheckedIcon*
                                                     *g:mdview_UncheckedIcon*
Drawn in place of `[x]` and `[ ]`. Both defaults are Nerd Font glyphs. >vim

    let g:mdview_CheckedIcon   = '󰱒 '
    let g:mdview_UncheckedIcon = '󰄱 '
<
                                                         *g:mdview_QuoteIcon*
Drawn in place of the `>` of a block quote, once per nesting level. >vim

    let g:mdview_QuoteIcon = '▎ '
<
                                                          *g:mdview_RuleChar*
The character a thematic break and a diff block's borders are drawn with. It
is repeated to fill the width, so a character wider than one cell simply
repeats fewer times. >vim

    let g:mdview_RuleChar = '─'
<
------------------------------------------------------------------------------
7.3 Backgrounds                                   *mdview-options-backgrounds*

Read |mdview-transparency| before setting either of these. On a transparent
colorscheme both are inert whatever you set them to, and that is deliberate.

                                                      *g:mdview_HeadingBlend*
Percent of the heading level's own foreground colour mixed into `Normal`'s
background to tint the heading's row. 0 turns heading backgrounds off. >vim

    let g:mdview_HeadingBlend = 15
<
                                                    *g:mdview_CodeBlockBlend*
Percent of white -- black on a light colorscheme -- mixed into `Normal`'s
background to tint a fenced code block's body. 0 turns the block background
off; it does not mean "a zero-strength one". >vim

    let g:mdview_CodeBlockBlend = 8
<
                                                   *g:mdview_BackgroundColor*
The colour to blend tints against, as a `0xRRGGBB` integer, when `Normal` has
no background of its own. -1 means "use `Normal`'s background, and skip the
tint if it has none". See |mdview-transparency|. >vim

    let g:mdview_BackgroundColor = -1
    " e.g. let g:mdview_BackgroundColor = 0x191724
<
------------------------------------------------------------------------------
7.4 Diff blocks                                          *mdview-options-diff*

A fenced block whose info string is `diff`, `patch` or `udiff` is coloured per
row rather than given one flat background.

                                                      *g:mdview_DiffHighlight*
Colour diff blocks at all. With it off they render as ordinary fenced code
blocks. >vim

    let g:mdview_DiffHighlight = 1
<
                                                         *g:mdview_DiffBorder*
Draw a rule above and below the block's body. The rule is a virtual line, so
it costs a screen row at each end. A block with an empty body gets none. >vim

    let g:mdview_DiffBorder = 1
<
The rule cannot go on the fence rows themselves: Neovim's own markdown
highlight queries hide those rows outright, and one plugin's extmark cannot
undo another's conceal.

                                                        *g:mdview_DiffPalette*
                                                       *mdview-diff-palettes*
Named colour sets for the three diff roles. An unrecognised name falls back to
`github`. >vim

    let g:mdview_DiffPalette = 'github'
<
    Palette         add       delete    hunk      Notes ~
    `github`          #3FB950   #FF5555   #D2A8FF   Default. Neutral red.
    `rose-pine`       #9CCFD8   #EB6F92   #C4A7E7   foam / love / iris.
                                                rose-pine has no green, so
                                                additions are a cyan; love
                                                skews pink.
    `vivid`           #00CC44   #FF3333   #B362FF   Saturated primaries.
    `muted`           #7FA87F   #BE8080   #A394C0   For a light or
                                                low-contrast terminal.

The colorscheme's own `DiffAdd` and `DiffDelete` are deliberately not used.
Those groups exist for |:diffthis|, where schemes routinely desaturate them
into blues and mauves, and a diff block that does not read as red and green
has no reason to be coloured.

                                                       *g:mdview_DiffAddColor*
                                                    *g:mdview_DiffDeleteColor*
                                                      *g:mdview_DiffHunkColor*
Override one role of the palette with a `0xRRGGBB` integer. -1 means "take it
from the palette". >vim

    let g:mdview_DiffAddColor    = -1
    let g:mdview_DiffDeleteColor = -1
    let g:mdview_DiffHunkColor   = -1
<
A removal colour wants its green and blue channels equal.
|g:mdview_DiffVibrance| preserves hue, so any imbalance is amplified as the
colour deepens: green above blue turns the red to rust, blue above green turns
it pink. This is why the default is `#FF5555` rather than GitHub's own
`#F85149`.

                                                      *g:mdview_DiffVibrance*
Percent to push the diff hues toward full saturation. 0 uses the colour as
given. Raising it deepens the colour without brightening it, which is usually
what "more vibrant" means; blending toward white does the opposite. >vim

    let g:mdview_DiffVibrance = 0
<
                                                         *g:mdview_DiffStyle*
How a diff row carries its colour. >vim

    let g:mdview_DiffStyle = 'text'
<
    `'text'`         Colour the row's text and leave the background alone.
                   Keeps a transparent window transparent.
    `'background'`   Tint the row's background and leave its text alone, the
                   way a forge renders one. Needs a background to tint: with
                   nothing to blend against it falls back to `'text'` rather
                   than painting over a window you chose to keep clear. See
                   |mdview-transparency|.

                                                         *g:mdview_DiffBlend*
Percent of the hue mixed into the background. `'background'` style only. >vim

    let g:mdview_DiffBlend = 30
<
------------------------------------------------------------------------------
7.5 When a change takes effect                        *mdview-options-timing*

Options fall into two groups, and the difference is worth knowing because a
change that appears to do nothing has almost always landed in the wrong one.

Colour options -- |g:mdview_HeadingBlend|, |g:mdview_CodeBlockBlend|,
|g:mdview_BackgroundColor|, and every `g:mdview_Diff*` option -- are read as
the highlight groups are computed, which happens once as `plugin/mdview.vim`
is sourced and again on every |ColorScheme|. Setting one afterwards changes
nothing until the next colorscheme change. To apply one immediately: >vim

    :let g:mdview_DiffPalette = 'rose-pine'
    :doautocmd ColorScheme
<
This is why a lazy.nvim spec sets them in `init`, not `config`.

Glyph options -- the icons, |g:mdview_RuleChar|, |g:mdview_DiffHighlight|
and |g:mdview_DiffBorder| -- are read every time a viewport is parsed. A
render is cached against the buffer's text, the visible rows and the window
width, so a changed glyph appears at the next event that moves one of those:
an edit, a scroll, or a resize. To apply one on the spot: >vim

    :MdviewDisable | MdviewEnable
<
|g:mdview_AutoEnable| and |g:mdview_Filetypes| are read on |FileType|, so they
affect the next buffer opened rather than the current one.

8. HIGHLIGHT GROUPS                                        *mdview-highlights*

Thirteen groups are `highlight default link`, so `:highlight link` or a
colorscheme overrides them the ordinary way:

    Group                    Links to ~
    MdviewH1 .. MdviewH6     `@markup.heading.1` .. `.6`   (the heading icon)
    MdviewBullet             `@markup.list`
    MdviewOrdered            `@markup.list`
    MdviewChecked            `@markup.list.checked`
    MdviewUnchecked          `@markup.list.unchecked`
    MdviewQuote              `@markup.quote`
    MdviewRule               `@punctuation.special`
    MdviewDiffBorder         `MdviewRule`

Because these link into `@markup.*`, and such links are dropped when the
colorscheme changes, mdview re-declares them from a |ColorScheme| autocmd of
its own.

------------------------------------------------------------------------------
8.1 Computed groups                               *mdview-highlights-computed*

Ten groups are computed rather than linked, from `Normal`'s background and the
options in |mdview-options-backgrounds| and |mdview-options-diff|:

    Group                    Is ~
    MdviewH1Bg .. MdviewH6Bg the heading row's background, one per level
    MdviewCodeBlock          a fenced block body's background
    MdviewDiffAdd            a `+` row in a diff block
    MdviewDiffDelete         a `-` row in a diff block
    MdviewDiffHunk           an `@@` row in a diff block

A computed group cannot use `default`: `nvim_set_hl()` refuses a `default`
definition once the group exists, which would freeze the colour at whatever
the first colorscheme produced -- the one thing a derived colour must not do.
So these are re-set outright on every |ColorScheme|.

The consequence surprises people. A plain `:highlight MdviewCodeBlock ...`
holds until the next colorscheme change and is then overwritten. To override a
computed group for good, set it from a |ColorScheme| autocmd of your own,
declared after the plugin has loaded so that yours runs second: >vim

    augroup MyMdviewColors
        autocmd!
        autocmd ColorScheme * highlight MdviewCodeBlock guibg=#21202e
    augroup END
<
The linked groups in |mdview-highlights| have no such problem.

9. TRANSPARENT BACKGROUNDS                               *mdview-transparency*

Neovim cannot read the terminal's own background colour. When `Normal` carries
no background -- `guibg=NONE`, which is how a deliberately transparent setup
works -- there is genuinely nothing for a tint to mix with.

mdview does not invent one. Guessing a stand-in paints an opaque block over a
window you chose to keep clear, which is a worse failure than no tint at all.
So on a transparent colorscheme:

- `MdviewCodeBlock` and `MdviewH1Bg` .. `MdviewH6Bg` are cleared. Code blocks
  and heading rows show whatever the window already shows.
- |g:mdview_DiffStyle| `'background'` degrades to `'text'`: diff rows are
  coloured, not tinted.
- |g:mdview_HeadingBlend| and |g:mdview_CodeBlockBlend| have no effect at any
  value.

The same is true without 'termguicolors' and outside a GUI, for the same
reason: there is no 24-bit colour to blend.

If you want the tints back without giving up transparency elsewhere, tell
mdview what the terminal's background is: >vim

    let g:mdview_BackgroundColor = 0x191724
<
That is the only thing that turns them on. The glyphs, rules, diff text colour
and every linked group work normally either way.

10. INLINE MARKUP IS NEOVIM'S                                 *mdview-inline*

mdview renders block structure only. Bold, italic, code spans and links are
concealed and coloured by Neovim's own bundled `markdown_inline` queries, not
by mdview, and they work because mdview sets 'conceallevel' to 2 in the
window.

Two things follow.

Inline rendering needs treesitter highlighting on for markdown. If you
do not start the highlighter -- `vim.treesitter.start()`, or an equivalent
from a plugin -- the emphasis markers and link brackets stay visible while
mdview's headings, bullets and quotes render normally.

mdview cannot turn inline concealment off. Conceal is additive: an extmark
saying "conceal" hides its range, and no extmark, priority or namespace says
"do not". The only mechanism that would work is shipping a replacement
`queries/markdown_inline/highlights.scm`, because the first such file on
'runtimepath' replaces the rest rather than adding to it -- at which point
mdview would own every inline colour in your markdown, and which file won
would depend on where mdview sat on 'runtimepath'. That is a takeover, not an
option, which is why there is no `g:mdview_ConcealLinks`.

The general form: mdview can add to what the runtime's queries draw, and can
never subtract from it.

11. LIMITATIONS                                          *mdview-limitations*

These are known, reproduced, and stated here rather than left for you to
discover.

Tables are not rendered at all. This was investigated and rejected, not
skipped. Glyph substitution helps only tables whose source is already aligned;
padding cells to a common width produced ~428-column rows on a real document.
Laying a table out to fit the window is the only approach that would help, and
it cannot be scrolled: a 21-row table lays out to 101 screen rows, and every
`winrestview()` topline inside a `conceal_lines` range collapses to the row
after the table, so the middle of the grid is unreachable by any scroll. If
tables are ever wanted, the shape that fits is a command that renders one into
a scratch buffer, where width is known and scrolling is ordinary.

Setext underlines stay visible. An underlined heading gets its row tinted;
the `===` or `---` beneath it is still drawn. Deliberate, and unresolved.

A setext heading nested in a list item tints its underline row too. At top
level the tint covers the text row alone. The construct renders two different
ways depending on nesting. Known defect, not fixed.

A thematic break inside a block quote wraps onto a second screen row. The
rule is sized against the raw line's width, which does not account for the
quote bar mdview inserts on the same row: in an 80-column window the row
consumes 82 cells. A `---` at top level, and one indented in a list item, are
both correct. Known defect, not fixed.

One buffer in two windows renders for one of them. Extmarks are
buffer-global, so mdview follows a single window's viewport, cursor and width
-- the current window when it shows the buffer, otherwise the first window
that does. The consequences:

- A second window scrolled elsewhere shows raw markdown outside the active
  window's viewport, while still carrying 'conceallevel' 2, so Neovim's own
  fence concealment still applies there.
- Rules are sized for the focused window. In a vertical split of unequal
  widths the unfocused window's rules are the wrong length, and re-size every
  time focus moves.
- The cursor's raw line is the focused window's cursor line.

'number' and friends leave a rule stale for one keystroke. `:set number`,
'signcolumn' and 'foldcolumn' each change how many cells are left for text and
fire no resize event at all, so a rule keeps its old length until the next
render for any other reason. A cursor move corrects it. Not worth a global
|OptionSet| autocmd to close a gap of one keypress.

A document that hides more than it shows draws its bottom rows raw.
Hiding a line makes room for another at the bottom, so mdview re-reads the
viewport until it settles, bounded at four windows' worth of lines and twelve
passes. A file of nothing but empty fenced blocks never settles; past the
bound, rows draw as written. Ordinary markdown settles on the first pass.

Ordered list markers are recoloured and nothing more. No conceal, no
replacement, no right-alignment. Aligning `8.` to the width of `10.` requires
scanning the whole enclosing list, which is not a property of the viewport,
and it shifts every following column on the line.

An unclosed fenced block renders nothing until its closing fence exists.

Rendering follows the buffer, not the window. `b:mdview` is buffer-scoped,
so |:MdviewDisable| in one window stops rendering everywhere the buffer is
shown.

Soft-wrap reflow is out of scope. mdview does not lay text out; it replaces
markers in place. Concealed text still counts toward where Neovim wraps a
line, which is why rules subtract the text they replace.

==============================================================================
12. HOW IT WORKS                                            *mdview-internals*

Useful if something looks wrong and you want to know where to look.

A treesitter query over the visible rows only -- not the document -- yields
block nodes; a Lua function turns those into a flat list of render operations
and returns it. Everything else is Vimscript: it places extmarks, owns the
window options, binds the autocmds, and computes the colours.

The op list is cached against three things: the buffer's `changedtick`, the
visible row range, and the window's text width. A bare cursor move re-places
the cached ops without re-parsing, and a move within one row does nothing at
all. That is why a glyph option changes nothing until one of the three moves
(|mdview-options-timing|).

Ops that hide or shift text -- conceal, replacement, inline text, a hidden
line -- are dropped on the cursor's own row. Ops that only colour are kept, so
a heading's background does not flicker as the cursor passes through it.

Every extmark lives in one namespace, `mdview`, which is what makes "clear
everything mdview drew" a single call. Inspect it with: >vim

    :lua ns = vim.api.nvim_create_namespace('mdview')
    :lua =vim.api.nvim_buf_get_extmarks(0, ns, 0, -1, {details = true})
<
